# Strengthen Hermes plan before building platform

**Verdict: conditionally solid, but not yet implementation-ready.** The plan has the right product center: compare one controlled Hermes change, isolate trials, grade outcomes, expose evidence, and report uncertainty rather than a raw leaderboard. Those choices match current guidance to use repeated trials, outcome-based grading, and paired comparisons ([Anthropic](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents); [Anthropic statistics](https://www.anthropic.com/research/statistical-approach-to-model-evals)). Its three-screen scope and decision to omit auth, multi-user support, and live streaming are sensible for a take-home. However, several Hermes assumptions are inaccurate, the experiment policy is underspecified, and the sandbox/grader boundary is not yet trustworthy. **This assessment is conditional: “Agent Evals Platform — Take-Home Assignment.pdf” is not present locally and no public copy was found, so exact requirement coverage cannot yet be verified.** In particular, the mandatory stack, timebox, scoring rubric, and rules on third-party frameworks remain unknown.

## Must fix before implementation

**P0 — Correct the Hermes execution design.** A Hermes profile is a mutable home containing configuration, credentials, sessions, memory, skills, logs, and state—not a native immutable `AgentConfig` ([profiles](https://hermes-agent.nousresearch.com/docs/user-guide/profiles)). Compile each platform config into a fresh per-trial home instead of mapping it 1:1 to a reusable profile. Prefer `hermes chat --oneshot --format stream-json` plus `--usage-file` for short-lived containers; it is explicitly designed for CI/orchestration and records main and auxiliary usage even on failure ([CLI reference](https://hermes-agent.nousresearch.com/docs/reference/cli-commands)). Do not treat Runs SSE as a full transcript: tool results are truncated previews; export complete session messages or the session store before teardown ([API server](https://hermes-agent.nousresearch.com/docs/user-guide/features/api-server)). Pin the image by digest, not a mutable tag.

**P0 — Make “self-learning off” explicit.** There is no single documented switch. The config compiler must disable both built-in memory stores, external memory tools/providers, background review, and skill mutation; write approval only stages pending writes and still mutates trial state ([memory](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory); [skills](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills)). A fresh container is clean only when `/opt/data`/`HERMES_HOME`, the workspace, and all external state are also fresh. Record served provider/model, auxiliary calls, and child-agent activity because `maxTurns` alone is not a complete work bound ([agent loop](https://hermes-agent.nousresearch.com/docs/developer-guide/agent-loop)).

**P0 — Separate isolation from security and grading.** Docker-per-trial prevents ordinary state leakage but is not by itself a security boundary. Specify no privileged mode or host Docker socket, dropped capabilities, CPU/RAM/PID/time limits, network policy, short-lived credentials, artifact limits, and guaranteed teardown. Run graders in a separate clean verifier container against copied final artifacts so the agent cannot edit tests, PATH, or grader dependencies; Harbor uses this exact separation ([Harbor task structure](https://www.harborframework.com/docs/tasks)). Keep oracle files, expected outputs, and `.git` history outside the agent workspace.

**P0 — Freeze the experiment before seeing final results.** Remove the result-contingent “fallback” from skill comparison to model comparison. Reserve unseen task variants, predeclare the changed factor, task weights, pass threshold, hard gates, retry/exclusion rules, and practical effect threshold. Randomize A/B order within each task-repeat block. A task budget timeout is an agent outcome; only sandbox/host/provider/grader failures qualify as infrastructure. Cap retries, retain every attempt, and report exclusions by arm. This follows guidance to hold tasks, scoring, budgets, and harness settings fixed ([OpenAI](https://openai.com/index/trustworthy-third-party-evaluations-foundations/)).

**P1 — Fix the statistical claim.** The paired task-level effect is a good primary endpoint, but bootstrapping only 20 task means ignores uncertainty from five stochastic repeats. Add a two-stage bootstrap that resamples tasks and then repeats within task, show raw task deltas, and state whether the claim applies only to the fixed suite or a wider task population. Remove the unsupported “≈10% detectable” statement until a pilot-based power calculation exists. Keep category results descriptive. Report pass@1, hard-gate failures, any/all-of-five reliability, cost per success, and initial/final infrastructure failure rates.

**P1 — Validate the LLM judge.** “Pinned and different” is insufficient. Blind configuration identity, give the judge no tools or secrets, treat candidate artifacts as hostile text, require schema-validated output with an `unknown` option, and calibrate against a small human-labeled set that includes borderline and prompt-injection cases. Model graders should be calibrated to human judgment and deterministic graders should remain primary ([Anthropic](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents); [OpenAI grader guidance](https://developers.openai.com/api/docs/guides/graders)).

## Nice to have after the core works

**P2 — Reuse more and claim less novelty.** Inspect already supports agents, sandboxes, replayable logs, and a viewer; Harbor supports arbitrary agents, container tasks, verifier rewards, a results viewer, and portable ATIF trajectories ([Inspect](https://inspect.aisi.org.uk/); [Harbor](https://github.com/harbor-framework/harbor); [ATIF](https://docs.harborframework.com/agents/atif)). Promptfoo and Langfuse also support agent traces and experiment comparison ([promptfoo](https://www.promptfoo.dev/docs/guides/evaluate-coding-agents/); [Langfuse](https://langfuse.com/docs/evaluation/experiments/experiments-via-sdk)). Narrow the differentiator to the Hermes adapter, controlled A/B contract, repeat-aware verdict, and explanation-first Vue UX. Spike Harbor behind a `Runner` interface; fall back to direct Docker if compatibility costs more than it saves.

**P2 — Stage the demo.** Run a four-task smoke test, then a ten-task demonstration, and make 20×2×5 optional. The proposed startup time, local concurrency, and $20–50 budget are estimates without evidence; measure them on the pinned setup. Add a machine-readable run manifest and downloadable experiment bundle only after the end-to-end evidence chain works.

## Conclusion

The winning submission is not the broadest platform. It is a reproducible Hermes experiment where a reviewer can trace an immutable configuration through isolated execution, independent grading, an honest uncertainty result, and concrete failure evidence in under a minute. Once the missing PDF is obtained, map every stated requirement to a screen, artifact, test, or documented limitation before finalizing scope.
